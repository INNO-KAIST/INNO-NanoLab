## 최근 작업
- **10-13 v1.6.1 A4 가로 전폭 카드**: 좁은 절차 칸(가로 1~2칸)에 전구체·시약 줄이 들어가면 글자가 세로로 잘리던 문제 → 카드 형식 '자동/세로 반장/가로 전폭'(계획 Print Preview, lot에 cardFmt 저장). 자동 = 가로 1~2칸 블록에 전구체 체크가 있거나 가로 1칸 블록에 시약이 있을 때 가로 전폭(277 mm, 왼쪽 82 mm 표·오른쪽 절차). 인쇄: 세로 카드는 A4 세로 2열, 가로 전폭 카드는 A4 가로 한 장에 위아래 2개(@page land, 카드 높이 ≤ 세로 절반이 되도록 축소하되 축소율만큼 카드를 넓혀 가로를 꽉 채움). 화면에선 칸 너비에 맞춰 축소 표시 + [크게 보기](실제 크기·수정 가능), lot 카드 창도 넓게.
- **10-13 v1.6.0 시약 직접 입력 · 프로토콜→레시피 흡수 · 칸 격자 블록 편집기**:
  시약: OA·ODE·OAm·MeOH 등은 절차 블록마다 '시약' 칸에 이름+mL로 직접 입력(블록 상세). 공식 계산은 [🧮 시약 계산기](계획 '시약' 섹션·블록 상세)에서 필요할 때만 열어 원하는 블록에 넣음. 카드 왼쪽 시약 표는 합치지 않고 넣는 순서대로(예: Oleic acid 2 → Methanol 3 → Oleic acid 3). 계획창의 '투입 조건' 공식 입력·용매 묶음(바인딩) UI 제거.
  전구체: 첨가/주입 블록에 Ln·Na·음이온 체크 → 카드 그 칸에 전구체 이름·mg 표시(체크 안 하면 표시 없음).
  예전 방식 데이터: 저장된 lot 카드는 그대로(60개 카드 텍스트 신·구 동일 확인). 옛 lot·레시피를 계획에 열면 그때 계산값을 블록에 옮겨 넣고 안내(저장한 레시피는 [저장] 전까지 원본 유지, 비교는 같은 변환으로 해 '다른 점' 오표시 없음).
  프로토콜 개념 제거: 기존 프로토콜은 '[절차] 이름' 레시피(절차만, 적용 시 성분 유지)로 한 번 옮김(id rp_<프로토콜id> 고정 — 기기 간 중복 없음, settings.protocols 데이터는 보존). 프로토콜 드롭다운·+새 프로토콜 제거. 새 계획 시작 절차 = 레시피 칸 [☆ 기본 절차로]로 지정(기존 기본/활성 프로토콜이 있으면 그것으로 자동 지정), 없으면 기본값.
  블록 편집기: 점선 칸 격자(3열)에 끌어 놓기·손잡이 크기 조절 — 다른 블록은 절대 밀리거나 크기가 바뀌지 않고, 겹치는 자리는 빨갛게 표시·거부. 블록 상세에 열·행·가로·세로 선택. 카드도 모든 블록을 좌표로 배치(자동 채움으로 제멋대로 움직이던 원인 제거). 예: 왼쪽 1×2 + 오른쪽 2×1 두 개 확인.
  남은 감사 항목 처리: 카드 전구체 손편집 키를 원소 기준(pe.Lu)으로(옛 lot은 행 번호 키 그대로 읽음), 다른 모드(Core/Shell) 초안도 창 닫기 경고, 블록을 고치면 '레시피와 다른 점'·[저장] 강조 즉시 갱신. 프로토콜 동기화 덮어쓰기·자동 ODE 총량 문제는 개념 제거로 해소.
- **10-13 v1.5.0 전수 점검 수정 (계획·기록·레시피·카드·ICP·동기화)** — 코드 2개 영역 정독 감사(50건 보고) → 실제 결함 약 40건 수정, 회귀 시나리오 9종 + 감사 시나리오 14종 통과.
  기록 불변: 시퀀스(바인딩) 프로토콜 카드도 lot 자기 절차로, upsertLot이 옛 lot에 현재 프로토콜을 찍던 것 제거, shell 용액 카드 OA/ODE/MeOH lot에 저장, 재저장 시 lot의 프로토콜 메타 유지, 성분·목표량이 바뀌면 낡은 카드 손값(전구체 숫자) 삭제.
  계획·레시피: 계획 안 용매 편집이 전역 프로토콜을 바꾸던 것 차단, 수정 중 shell 값이 설정 변경에 덮이던 것 차단, 레시피 적용 취소 시 선택만 바뀌던 것, 가져오기가 선택을 바꾸던 것, 지운 레시피가 [저장]으로 되살아나던 것, 저장 직후 '다른 점: 성분' 오표시, 다른 점 비교 범위(목표량·시약 조건·shell 조건·카드 문구) 확대, 지워진/번호 바뀐 lot을 수정 저장해 되살리던 것, 지운 번호 재사용(이제 다음 번호는 지운 번호도 건너뜀), 추정 레시피가 기록으로 굳던 것, 마법사 '현재 절차'가 계획 절차를 버리던 것·레시피 동기화 누락, 카드 제목 수정 후 인쇄·번호 갱신, shell 자기 자신을 source로 고를 수 있던 것, 수정 중 레시피를 바꿔도 카드 손편집 유지.
  카드·화면: shell 카드 모달에서 용액 카드 편집이 shell 카드로 저장되던 것, 카드 제목 편집 → lot 이름, 인쇄 시 모달이 같이 찍히던 것, 되돌리기 후 다른 화면에 기록표가 그려지던 것, 대시보드 ICP 미분석 수, 레시피 칸 'Lot N 만들 때' 표시.
  ICP: '/'가 든 라벨로 저장 시 클라우드 동기화가 영구히 막히던 것(문서 id 정리), 대상 외 원소가 수율 분자에만 들어가던 것(OES·통합·MS), MS 0 이하 값을 '정량 양호'로 보던 것, 원소 없는 그룹 저장, 통합 OES 기록 상세·원소별 희석, 엑셀 내보내기 희석·단위·상태 열, 숫자 라벨(157)이 표준으로 잡히던 것, 파일명 8자리 날짜, λ 일치 기준, 같은 id 덮어쓰기, '–%' 표시.
  동기화: 계획 작성 중 원격 변경으로 화면이 다시 그려져 입력이 사라지던 것, 설정만 내려받았을 때 화면 미갱신, 개인 레시피 버전 기록이 랩 공용·내보내기에 섞이던 것.
  남김(구조 변경 필요): 프로토콜이 settings 문서 한 덩어리로 동기화(기기 간 마지막 저장이 이김), 카드 손편집 키가 행 번호 기반, 시퀀스 카드의 자동 ODE 총량이 현재 설정을 읽음, 다른 모드(Core/Shell) 초안의 창 닫기 경고.
- **10-13 v1.4.9 절차 배지 오표기 수정**: '절차 기록됨 · NaLnF4 (thermal decomposition)' — 배지가 lot.protocol.name(저장 당시 '전역 활성 프로토콜' 이름, 1.4.8 이전 저장분)을 띄워 Cl lot(WJ-0161c)이 NaLnF4로 보였음. 절차 내용은 Cl이 맞았음. → 배지에서 프로토콜 이름 제거, '이 lot의 절차 기록됨 · 레시피 X'(저장 당시 레시피 이름). 카드 시약 중 계산값 없는 행(F 없는 계의 Methanol '- mL') 숨김.
- **10-13 v1.4.7–1.4.8 레시피 절차가 사라지던 경로 차단 + 버전 기록**: 계획의 절차가 '전역 활성 프로토콜'(동기화되는 설정)에 묶여 있어, 다른 탭·기기·프로토콜 선택으로 활성 프로토콜이 바뀌면 열려 있던 계획의 절차가 그 프로토콜 것으로 조용히 교체됐고, 그 상태로 [저장]하면 레시피(예: NaLnF4)가 다른 절차(Na3LnCl6)로 덮어써짐.
  → 계획 절차는 처음 한 번만 채우고, 사용자가 프로세스 편집기에서 프로토콜을 직접 바꿀 때만 교체. 레시피 protocolId·시약 정의도 전역 값이 아니라 계획(ctx.proto.srcId/reagents) 기준. 내장 기본 프로토콜은 'builtin'(계획 상수로 매번 계산).
  레시피 [저장] 때마다 직전 내용을 최대 10개 보관 + [버전] 버튼(계획에 불러오기 → [저장]으로 확정). 동기화 때 옛 앱 버전이 올린 proto 없는 레시피가 proto를 지우지 않게 병합. prompt() 차단도 알림.
- **10-13 v1.4.6 저장 단위를 레시피 하나로**: 계획창의 '프로토콜에 반영/프로토콜 값으로' 막대 제거(레시피 [저장]과 따로 놀아 혼란). 이제 비교 대상은 선택한 레시피 — 성분·절차(블록 구성)가 레시피와 다르면 안내 + [저장] 강조, 누르면 보이는 그대로 덮어씀. 수정 모드에선 'lot만 바뀜, 레시피 무관' 안내. 프로토콜은 새 계획의 시작 틀로만 쓰임.
- **10-13 v1.4.5 레시피 = 프로세스 구조 전체**: 레시피·lot 스냅샷은 절차 블록 배열 전체(종류·순서·위치 gx/gy·크기 gw/gh·문구·시퀀스 바인딩)를 담는다 — 숫자만이 아니라 블록 구성이 다른 레시피도 그대로 복원(검증: 블록 2개 삭제·진공/퍼지 추가·위치/크기 변경한 레시피 B → 적용·lot 카드·수정 모두 동일 구조).
  레시피에 프로토콜 시약 정의(reagents)·이름도 담고, 가리키던 프로토콜이 지워졌으면 적용 시 그 정의로 프로토콜을 되살림.
- **10-13 v1.4.4 기록 ↔ 레시피 분리 · 절차 기록 표시 · 확인창 차단 알림**: lot은 저장 순간의 성분·절차·시약을 통째로 갖고(레시피와 분리), 레시피 이름도 저장 당시 값으로 고정 — 레시피를 고치거나 지워도 기록은 그대로(삭제 시 해당 lot 번호 안내).
  lot 서랍·카드에 '절차 기록됨 / 절차 기록 없음 — 현재 기본 절차로 표시 중' 배지(옛 lot 중 기본 프로토콜로 저장된 것은 절차가 애초에 저장되지 않았음).
  브라우저가 confirm 창을 차단하면 작업이 조용히 취소되던 문제 → 즉시 알림 토스트.
- **10-13 v1.4.3 레시피 선택 = 이 계획(lot)의 것**: 레시피 칸이 전역 '마지막 사용 레시피'(settings.activeRecipeId)를 보여 줘, 지난 lot을 [수정]으로 열어도 최근 레시피가 떴다.
  → 선택은 계획별(ctx.recipeId), lot 저장 시 recipeId·recipeName 기록, [수정]으로 열면 그 lot의 레시피 표시(기록 없는 옛 lot은 '레시피 기록 없음', 성분·절차가 같은 레시피가 하나뿐이면 '(추정)'). 새 계획은 '선택 안 함'으로 시작.
- **10-12 v1.4.2 절차 스냅샷 — lot·레시피마다 자기 온도·시간**: 저장된 lot 카드가 '현재 활성 프로토콜'의 절차로 그려져, 한 곳에서 온도를 바꾸면 모든 lot 카드가 같이 바뀌었다(WJ-158~161c 210/240/270/300 ℃가 하나로 보임). 레시피도 프로토콜 id만 저장해 같은 프로토콜을 쓰는 레시피는 절차가 같았다.
  → lot 저장 시 계획창에 보이는 절차(steps·카드 문구)를 lot.protocol에 그대로 저장하고 카드는 그것으로 그림. 레시피에 절차(proto) 저장·적용 시 복원. 계획창 절차는 계획 전용(ctx.proto) — [프로토콜에 반영]/[프로토콜 값으로] 막대. [수정]으로 열면 그 lot의 절차를 불러옴. 레시피 시약 조건도 '이 계획에만' 값 반영.
- **10-12 v1.4.1 lot 번호·수정 모드·삭제 수정**:
  ① **Lot 번호 칸** 신설(계획창 Core·Shell). 입력한 번호로 저장 — 전엔 샘플명만 바뀌고 내부 serial은 항상 다음 빈 번호. 샘플명에 `WJ-0157c`처럼 번호를 쓰면 그 번호로 맞춤. 이미 있는 번호면 저장 막음.
  수정 중 번호를 바꾸면 lot을 새 번호로 옮기고 ICP 기록·Shell source 연결도 함께 이동.
  ② **레시피 적용·✨새 합성 프로세스 마법사**가 계획을 새로 만들면서 수정 모드(editSerial)·번호·이름·날짜를 버리던 문제 → 유지.
  ③ 수정 저장이 lot을 통째로 덮어써 계획창에 없는 값(TEM 반지름 등)·프로토콜 스냅샷이 사라지던 문제 → 기존 값 위에 덮어씀, 프로토콜은 수정 중 바꿨을 때만 새로 찍음.
  ④ **삭제**: 브라우저 confirm 창에 의존 → 창이 차단되면 조용히 아무 일도 안 일어남. 두 번 눌러 확정 + 8초 되돌리기로 교체. lot 서랍에도 삭제 버튼. ICP 기록 삭제도 같은 방식.

## 교훈 · 트러블슈팅
- (v1.6.0) CSS grid에서 일부 블록만 좌표가 있고 나머지가 span만 있으면 dense 자동 배치가 빈칸을 메우며 위치가 바뀐다 — 카드·편집기 모두 모든 블록을 resolveLayout 좌표로 명시 배치. 충돌 해소를 위해 다른 블록을 밀어내는 방식은 사용자가 예측할 수 없으므로, 겹치면 거부하는 쪽이 맞다.
- 편집 중인 문서(계획)는 동기화되는 전역 설정에 '참조'로 묶이면 안 된다 — 다른 곳에서 설정이 바뀌면 화면이 조용히 바뀌고, 그걸 저장하면 엉뚱한 레시피가 덮어써진다. 처음에 복사(스냅샷)하고, 사용자의 명시적 행동에서만 교체.
- 덮어쓰기 저장에는 버전 기록을 남긴다(되돌릴 길).
- 기록(lot)은 저장 시점의 모든 계산 입력을 스냅샷으로 가져야 한다 — 공용 설정(프로토콜)을 참조만 하면 설정을 고칠 때 지난 기록이 같이 바뀐다(09-29 reagentsUsed와 같은 종류의 결함).
- 삭제·확인을 `confirm()`에만 맡기면, 사용자가 "이 페이지의 대화상자 차단"을 한 번 누른 뒤로는 confirm이 바로 false를 돌려 버튼이 죽은 것처럼 보인다 → 앱 안 2단계 확인 + 되돌리기.
- 계획창을 새 ctx로 갈아끼우는 경로(레시피·마법사)는 수정 대상(editSerial)을 반드시 이어받아야 한다.
- ICP-MS 저농도(수 ppb 이하)에서는 검정 blank가 높게 잡히면 모든 값이 일정량 낮게(무첨가 시료는 음수) 나온다 → 무첨가 측정 중앙값으로 오프셋을 추정·보정하고, 보정 후 1 ppb 표준 회수율로 교차 확인.
- Qtegra 보고서는 표준을 두 번(검정 요약·분석별) 싣는다 → (index, 이름)으로 합쳐야 중복이 안 생긴다.
- ICP-OES 라벨이 순수 숫자("150")면 표준으로 분류된다(기존 규칙) → 샘플은 "150c"처럼 문자를 붙일 것.
- 계획창에서 고친 값이 전역 기본값을 조용히 바꾸면, 지난 lot 카드까지 바뀐다(카드가 현재 기본값으로 재계산) → 값은 lot 에 기록하고 그 값으로 그린다.
- 합성 카드(인쇄물)는 앱 스타일과 분리 — 글꼴·줄높이·줄바꿈 규칙이 바뀌면 카드 높이(402px 기준)가 변한다.
- (유원정) 빌드는 기밀 데이터가 있으므로 절대 배포 대상에 넣지 않는다(manifest 는 배포용만).
