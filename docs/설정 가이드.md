**구성원이 실제로 받는 것은 `INNO NanoLab (설정용).html` + `INNO NanoLab (setup).bat` + `INNO NanoLab (setup).html` 세 개뿐**입니다. 배포용·본편은 소유자가 관리합니다.

> 이름이 비슷하지만 역할이 다릅니다: `INNO NanoLab (setup)…`은 **실행·선택 메뉴(런처)**이고, 실제로 기준 DB를 시딩하는 앱은 **`INNO NanoLab (설정용).html`**입니다. bat을 실행하면 런처가 열리고, 거기서 [설정용] 버튼을 누르면 됩니다.

기준 데이터베이스 = 계산 파라미터 · Precursor Database · ICP 간섭 DB(166 기준피크 · 기준원소 18종) · 내장 합성 카드 프로토콜. 클라우드(Firestore `users/{내 계정}/meta/refdata_*`)에 저장되며, 앱에서 이 값들을 고치면 모든 기기에 자동 반영됩니다. 시약 조건·과량·Shell 용액 농도 같은 계산 파라미터는 **합성 계획 탭에서 결과를 보면서** 고치고(거기서 고친 값이 다음 계획의 기본값이 됩니다), Precursor Database와 새 계획 기본값(Stock volume)만 설정 탭에 남아 있습니다.

> **시퀀스 기반 커스텀 프로토콜**(사용자가 [+ 새 프로토콜]로 만든 것)과 **'기본값으로 지정'** 설정은 기준 DB가 아니라 **각 계정의 사용자 설정**으로 저장·동기화됩니다(합성·ICP 기록과 동일하게 계정 전용). 내장 '기본값' 프로토콜만 기준 DB(코드)에 포함됩니다.

## 2. 최초 구축 (소유자 전용 — 이미 완료된 상태의 기록)

1. Firebase 콘솔에서 **연구실 공용 프로젝트(현재 `inno-nanoil`)**: Authentication → Google 로그인 활성화 · Firestore 생성 · 보안규칙 게시(`users/{uid}` 본인만 읽기/쓰기 + `labs/{랩ID}` 공용 레시피 — 설정 탭 **[설정 가이드]** 창 4번 항목의 **[규칙 복사]** 내용 사용) · Authentication → Settings → **승인된 도메인**에 배포 도메인 추가. firebaseConfig는 모든 빌드에 내장되어 있어 붙여넣을 것이 없습니다.
2. **시딩(1회)**: `INNO NanoLab (setup).bat`을 본편과 같은 폴더에 두고 실행 → 선택 메뉴에서 **본편** 클릭 → Google 로그인 → 연구 데이터 + 기준 DB가 클라우드에 자동 업로드.
3. **웹 배포**: `(배포용)` 파일을 GitHub 저장소(WonJeong-Dev/INNO-NanoLab)에 **`index.html`로 개명 업로드** → Settings → Pages = Deploy from a branch / main / (root) → Firebase [Authentication → Settings → 승인된 도메인]에 `wonjeong-dev.github.io` 추가.
   - **아이콘**: `favicon.ico`와 `apple-touch-icon.png`(180×180)를 **저장소 루트**(index.html과 같은 위치)에 함께 올리면 브라우저 탭·북마크와 iOS "홈 화면에 추가"에서 코어-셸 아이콘이 표시됩니다. 배포용 head에 링크 태그(`rel="icon"`·`rel="apple-touch-icon"`)가 내장돼 있어 파일만 루트에 있으면 됩니다. 아이콘을 바꿔도 브라우저 캐시 때문에 예전 것이 보이면 Ctrl+F5(또는 iOS는 홈 화면 아이콘 삭제 후 재추가).

> config를 바꾼 새 빌드를 배포할 때는 반드시 **세 파일(본편·배포용·설정용)의 config를 모두 동일**하게 맞추세요. 배포용(웹)만 바꾸고 설정용을 그대로 두면, 설정용은 옛 프로젝트에 시딩하고 웹은 새 프로젝트를 읽어 초기설정 창이 무한 반복됩니다.

## 3. 새 기기 추가 (소유자 본인의 다른 PC·휴대폰)

배포 주소(https://wonjeong-dev.github.io/INNO-NanoLab/) 접속 → Google 로그인 → 끝. 데이터·기준 DB·설정(프로토콜 포함)이 자동으로 내려오고 이후 실시간 동기화됩니다. 수동 백업/복원 절차는 없습니다.

## 4. 연구실 구성원 배포

**전달물**: `INNO NanoLab (설정용).html` + `INNO NanoLab (setup).bat` + `INNO NanoLab (setup).html` (같은 폴더). 메신저·USB·내부 NAS로만 전달하세요 — **기준 DB가 내장되어 있으므로 공개 웹 업로드 금지**.

구성원 절차:

1. **폴더 준비** — 빈 폴더에 받은 세 파일(`INNO NanoLab (설정용).html`·`INNO NanoLab (setup).bat`·`INNO NanoLab (setup).html`)을 함께 넣습니다.
2. **최초 1회 시딩** — `INNO NanoLab (setup).bat` 실행(Python 필요) → 브라우저에 **선택 메뉴**가 열립니다 → **[설정용] 버튼 클릭** → **본인 Google 계정으로 로그인**. 이 순간 기준 DB가 본인 계정 클라우드에 자동 시딩됩니다(별도 업로드 절차 없음). 상단 칩이 "클라우드 동기화 중"으로 바뀌고 설정 탭의 Precursor Database·파라미터에 값이 채워지면 완료입니다.
3. **이후** — 아무 기기에서나 배포 주소 접속 → **같은 계정**으로 로그인 → 바로 사용.

> 초기설정 가능한 파일이 폴더에 여러 개면(예: `설정용`·`본편`) 선택 메뉴에 버튼으로 모두 나타납니다. 구성원은 **설정용**을 누르세요(메뉴에서 "권장"으로 표시됩니다). `배포용`은 "웹 전용 · 로컬 초기설정 불가"로 표시되니 로컬에서는 누르지 마세요.

알아둘 점: 각자의 합성·ICP 기록과 커스텀 프로토콜은 **각자 계정 전용 공간**에 저장되어 서로 보이지 않습니다(Firestore owner-only 규칙). 다만 Firebase 프로젝트 소유자(유원정)는 콘솔에서 프로젝트 데이터 관리 권한을 가지므로 이 점을 구성원에게 고지하고 사용하세요. 무료 할당량은 연구실 규모에 충분합니다. bat 없이 파일을 더블클릭하면 로컬 저장으로만 동작합니다(로그인 팝업은 localhost/https 전용).

레시피를 함께 쓰려면 섹션 5를 이어서 보세요 — 시딩과는 별개의 1회 설정입니다.

**연구실 표준 파라미터가 바뀌면**: 새 설정용 파일을 재배포 → 구성원이 한 번 실행·로그인하면 본인 클라우드 기준 DB가 자동 갱신됩니다(각자 커스텀한 정상 설정값·프로토콜은 유지, 비정상 0 값만 자동 복원).

## 5. 랩 공용 레시피 (선택)

기준 DB 시딩과는 **별개**입니다. 시딩은 계산 파라미터·물질 DB를 나눠 주는 것이고, 이쪽은 **레시피(조성 · 전구체 · 투입 방식 · 과량 · 시약 조건 · 합성 절차 묶음)**를 서로 보이게 하는 기능입니다. 개인 합성·ICP 기록은 여전히 공유되지 않습니다.

절차 전문은 앱 안에 있습니다 — 설정 탭 **[랩 공유 가이드 — 무엇을 해야 하나요?]**. 콘솔 화면 그대로 따라 할 수 있게 적어 두었으니, 실제 작업은 그 창을 열어 놓고 하세요. 여기서는 무엇이 필요한지만 정리합니다.

**전제**: Firebase 동기화가 이미 켜져 있어야 합니다(섹션 2·4 완료 상태).

**관리자(Firebase 콘솔 접근 권한자 — 현재 유원정)가 1회**

1. 설정 탭 [설정 가이드] 또는 [랩 공유 가이드] 창의 **[규칙 복사]** → Firestore 규칙 탭에 게시. `labs/{랩ID}/members`는 앱에서 못 고치도록 `allow write: if false`로 잠겨 있습니다 — 멤버 등록은 콘솔에서만 가능하다는 뜻이고, 이것이 아무나 자기를 멤버로 넣지 못하게 막는 장치입니다.
2. **랩 ID**를 정합니다(영문 소문자·숫자·하이픈, 예: `nanolab`). 대소문자까지 구분하므로 전원이 똑같이 입력해야 합니다 — 오타가 있으면 그 사람만 빈 서랍을 봅니다.
3. 멤버가 보내온 UID를 콘솔 Firestore에 등록: `labs / {랩ID} / members / {UID}`. 사람이 늘면 이 문서만 추가하면 됩니다.

**멤버(관리자 본인 포함)가 1회**

1. 앱에서 Google 로그인(동기화가 켜져야 UID가 생깁니다).
2. 설정 탭 **내 UID** 옆 [복사] → 관리자에게 전달.
3. 등록됐다는 연락을 받으면 설정 탭 **랩 공용 레시피 — 랩 ID** 칸에 약속한 이름 입력 → Enter. 합성 계획 탭 레시피 목록에 공용 묶음이 생깁니다.

**쓰는 법**: 공용 레시피는 **읽기 + 적용**만 되고 저장·삭제는 잠깁니다. 고치려면 [내 것으로 복사] — 그때부터 내 레시피이고 원본은 그대로입니다. 내가 올린 것은 [랩에서 내리기]로 공용에서만 뺄 수 있습니다(내 사본은 남음). 앱에서 남의 레시피를 덮어쓸 경로 자체가 없는 것은 의도된 설계입니다.

**랩 ID 칸을 비워 두면** 이 기능은 꺼지고 개인 레시피만 씁니다. 기존 사용에는 아무 영향이 없습니다.

## 6. 업데이트를 받았을 때 (소유자 전용)

새 버전 파일을 받으면: ① 로컬 폴더의 본편·배포용·설정용 파일 교체 ② GitHub `index.html`을 새 배포용으로 교체(브라우저에 예전 화면이 보이면 Ctrl+F5) ③ **본편에서 1회 로그인** — 기준 DB 해시가 바뀐 경우 자동 재업로드되어 배포판·구성원 흐름에도 새 파라미터가 전달됩니다.

**Firebase 프로젝트나 config가 바뀐 빌드를 배포한 경우**: 앱은 브라우저에 한 번 저장된 config를 내장값보다 우선합니다. 따라서 기존에 쓰던 기기에서는 해당 사이트의 **브라우저 데이터(사이트 저장소)를 한 번 삭제**하거나 로그인 화면 고급의 config 입력칸을 비운 뒤 새로고침해야 새 프로젝트로 접속됩니다. 새 프로젝트는 비어 있으므로, 소유자는 본편으로·구성원은 설정용으로 각각 1회 재시딩해야 데이터가 채워집니다.

## 7. 문제 해결

- **"데이터베이스 없음 / 초기설정" 창이 계속 뜸** → 대개 아래 셋 중 하나입니다.
    - *배포용으로 초기설정하려 함* — 배포용은 기준 DB를 심지 못하고 클라우드에서 **받기만** 합니다. 최초 시딩은 반드시 **설정용**(소유자는 본편)으로 하세요. 선택 메뉴를 쓰면 배포용은 "로컬 초기설정 불가"로 표시됩니다.
    - *브라우저에 옛 config가 남음* — 이전에 다른 프로젝트로 접속한 적이 있으면 그 config가 저장돼 계속 옛(빈) 프로젝트를 봅니다. 사이트 저장소 삭제 후 새로고침, 또는 로그인 화면 고급 config 칸을 비우면 내장 config가 다시 적용됩니다.
    - *계정 불일치* — 시딩한 Google 계정과 웹에서 로그인한 계정이 다르면 빈 공간을 봅니다. 같은 계정으로 로그인하세요.
- **선택 메뉴가 "파일을 찾지 못했습니다"라고 함** → HTML 파일이 `INNO NanoLab (setup).bat`·`INNO NanoLab (setup).html`과 같은 폴더에 있는지 확인하세요.
- **bat을 실행해도 메뉴가 안 뜨고 기본 파일 목록만 보임** → 폴더에 `INNO NanoLab (setup).html`이 없는 경우입니다(런처 없이도 목록에서 직접 클릭하면 동작). 이때 폴더에 `index.html`이 있으면 목록 대신 그 파일이 자동으로 열리니 주의하세요.
- **GitHub 주소에서 README만 보임** → 저장소 루트에 `index.html`이 없는 것. 개명 후에도 보이면 브라우저 캐시(Ctrl+F5 또는 시크릿 창).
- **로그인 팝업이 안 뜸** → 파일을 직접(더블클릭) 연 경우. bat(localhost) 또는 배포 주소에서 로그인하세요. 배포 주소라면 승인된 도메인 등록 확인.
- **카드/계산 값이 0으로 보임** → 과거 동기화 오염 흔적. 현재 버전은 로드·로그인 시 자동 복원(자가치유)하므로 새 버전으로 열고 로그인 한 번이면 해결됩니다. Shell 용액 Methanol 등 개별 값도 로드 시 자가치유됩니다.
- **랩 공용 목록이 안 보이거나 "멤버로 등록되어 있지 않습니다"** → 명부에 내 UID 문서가 없거나, UID·랩 ID에 오타(대소문자 포함). 설정 탭에서 UID를 다시 복사해 관리자에게 전달하고, 랩 ID 철자를 서로 맞춰 보세요.
- **삭제 실수** → 위험 작업 직전 자동 스냅샷(최근 3개, 설정 탭) + JSON 백업으로 복구. 개별 삭제는 서버에 흔적이 남아 콘솔 복구도 가능.
